# 게시판 API 기능명세

기본 주소는 `http://localhost:8080`입니다. 실행 방법은 [README](../README.md), 실행 가능한 명세는 `/swagger-ui.html`, OpenAPI JSON은 `/v3/api-docs`에서 제공합니다. 웹 화면은 게시글 목록(`/`)과 상세(`/post.html?id=게시글ID`)를 구현했습니다. Docker Compose의 앱·DB 포트는 로컬 과제용으로 호스트의 `127.0.0.1`에만 바인딩합니다.

## 공통 규칙

- JSON 요청·응답은 UTF-8입니다. 파일 업로드는 `multipart/form-data`, 다운로드는 바이너리 응답입니다.
- 인증은 `JSESSIONID` 세션 쿠키로 유지합니다. 세션 유휴 만료 시간은 30분입니다.
- 모든 POST·PUT·DELETE 요청에는 `XSRF-TOKEN` 쿠키와 같은 값의 `X-XSRF-TOKEN` 헤더가 필요합니다.
- `GET /api/auth/csrf` → 회원가입 → 로그인 → CSRF 재발급 순서로 시작합니다. 로그인·로그아웃 후에는 토큰을 다시 발급받습니다.
- Swagger UI는 발급된 CSRF 쿠키를 읽어 헤더를 자동 설정합니다. 다른 클라이언트는 쿠키 저장과 헤더 설정을 직접 처리합니다.
- 수정은 `PUT`으로 제목·본문 또는 댓글 내용을 모두 전달합니다. 작성자 ID는 요청 본문에서 받지 않고 로그인 사용자로 결정합니다.
- 생성은 `201`, 조회·수정은 `200`, 삭제·로그아웃은 본문 없는 `204`를 반환합니다.

## 도메인 관계와 권한

| 관계 | 의미 |
| --- | --- |
| 사용자 1 : N 게시글 | 게시글마다 작성자 1명이 존재 |
| 사용자 1 : N 댓글 | 댓글마다 작성자 1명이 존재 |
| 게시글 1 : N 댓글 | 댓글은 하나의 게시글에 속함 |
| 게시글 1 : N 첨부파일 | 파일은 하나의 게시글에 속하며 게시글 작성자가 관리 |

비회원은 게시글·댓글·파일 목록과 게시글 상세·파일 다운로드를 이용할 수 있습니다. 로그인 사용자는 게시글과 댓글을 작성할 수 있습니다. 게시글 수정·삭제와 파일 추가·삭제는 게시글 작성자만, 댓글 수정·삭제는 댓글 작성자만 가능합니다. 게시글 작성자라도 다른 사용자의 댓글을 개별 수정·삭제할 수 없습니다.

게시글을 삭제하면 댓글은 DB 외래키의 `ON DELETE CASCADE`로 함께 삭제하고 파일 메타데이터도 삭제합니다. 실제 파일은 DB 커밋 후 삭제합니다. 파일 하나를 삭제해도 게시글과 댓글은 유지됩니다.

## 인증

| 메서드·경로 | 입력 | 정상 응답 |
| --- | --- | --- |
| `GET /api/auth/csrf` | 없음 | CSRF 토큰 및 쿠키, 200 |
| `POST /api/auth/signup` | 이메일·닉네임·비밀번호 | 사용자 정보, 201 |
| `POST /api/auth/login` | 이메일·비밀번호 | 사용자 정보·로그인 세션, 200 |
| `GET /api/auth/me` | 로그인 세션 | 사용자 정보, 200 |
| `POST /api/auth/logout` | CSRF 토큰 | 현재 세션·쿠키 무효화, 204 |

회원가입은 자동 로그인하지 않습니다. 로그인 시 세션 ID를 교체합니다. 로그아웃은 유효한 CSRF 토큰이 있으면 로그인 세션이 없어도 `204`를 반환합니다.

회원가입 요청:

```json
{"email":"test@example.com","nickname":"tester","password":"password123"}
```

로그인 요청:

```json
{"email":"test@example.com","password":"password123"}
```

회원가입·로그인·내 정보 응답 예시:

```json
{"id":1,"email":"test@example.com","nickname":"tester"}
```

이메일은 필수·이메일 형식·최대 100자·중복 불가, 닉네임은 공백만 허용하지 않는 2~100자입니다. 비밀번호는 회원가입 시 8자 이상이고, 가입·로그인 모두 UTF-8 72바이트 이하입니다. 비밀번호는 BCrypt 해시로 저장하며 응답에 포함하지 않습니다.

## 게시글

| 메서드·경로 | 기능 | 권한 |
| --- | --- | --- |
| `GET /api/posts` | 목록·제목/본문 검색 | 공개 |
| `GET /api/posts/{postId}` | 상세 조회 | 공개 |
| `POST /api/posts` | 작성 | 로그인 |
| `PUT /api/posts/{postId}` | 제목·본문 수정 | 게시글 작성자 |
| `DELETE /api/posts/{postId}` | 게시글과 하위 데이터 삭제 | 게시글 작성자 |

작성·수정 요청:

```json
{"title":"첫 번째 게시글","content":"게시글 본문입니다."}
```

제목은 1~200자, 본문은 1~10,000자이며 공백만 입력할 수 없습니다. 작성·상세·수정 응답 예시:

```json
{
  "id":1,
  "title":"첫 번째 게시글",
  "content":"게시글 본문입니다.",
  "author":{"id":1,"nickname":"tester"},
  "createdAt":"2026-09-07T08:00:00Z",
  "updatedAt":"2026-09-07T08:00:00Z"
}
```

파일은 게시글 생성 응답의 `id`를 사용해 파일 API로 별도 첨부합니다. 작성자는 수정으로 바뀌지 않으며 생성 시각은 유지되고 수정 시각은 갱신됩니다.

## 댓글

| 메서드·경로 | 기능 | 권한 |
| --- | --- | --- |
| `GET /api/posts/{postId}/comments` | 댓글 목록 | 공개 |
| `POST /api/posts/{postId}/comments` | 댓글 작성 | 로그인 |
| `PUT /api/posts/{postId}/comments/{commentId}` | 댓글 수정 | 댓글 작성자 |
| `DELETE /api/posts/{postId}/comments/{commentId}` | 댓글 삭제 | 댓글 작성자 |

작성·수정 요청은 `{"content":"좋은 글 감사합니다."}`입니다. 내용은 1~2,000자이며 공백만 입력할 수 없습니다. 응답 예시:

```json
{
  "id":2,
  "postId":1,
  "content":"좋은 글 감사합니다.",
  "author":{"id":2,"nickname":"reader"},
  "createdAt":"2026-09-07T08:01:00Z",
  "updatedAt":"2026-09-07T08:01:00Z"
}
```

댓글의 `commentId`가 존재하더라도 경로의 `postId`에 속하지 않으면 `404`를 반환합니다. 존재하지 않는 게시글의 댓글 목록도 `404`입니다.

## 페이징과 검색

게시글·댓글 목록은 `page`와 `size`를 사용합니다.

| 파라미터 | 기본값 | 범위·동작 |
| --- | --- | --- |
| `page` | 0 | 0부터 시작, 음수 불가 |
| `size` | 20 | 1~100 |
| `keyword` | 없음 | 게시글 목록 전용, 최대 100자 |

게시글은 작성 시각·ID 내림차순, 댓글은 작성 시각·ID 오름차순으로 정렬합니다. 게시글 검색은 제목 또는 본문에 검색어가 포함된 게시글을 반환하며 대소문자를 구분하지 않습니다. 검색어의 앞뒤 공백은 제거하고 빈 검색어는 전체 조회합니다. `%`·`_`는 일반 문자로 검색합니다.

```text
GET /api/posts?page=0&size=20&keyword=Spring
GET /api/posts/1/comments?page=0&size=20
```

목록 공통 응답은 다음 구조이며 `content`에 해당 게시글 또는 댓글 응답 객체가 들어갑니다. 범위를 벗어난 페이지는 빈 `content`를 반환합니다.

```json
{
  "content":[],
  "page":0,
  "size":20,
  "totalElements":0,
  "totalPages":0,
  "first":true,
  "last":true
}
```

## 첨부파일

| 메서드·경로 | 기능 | 권한 |
| --- | --- | --- |
| `GET /api/posts/{postId}/files` | 파일 목록 | 공개 |
| `POST /api/posts/{postId}/files` | 파일 업로드 | 게시글 작성자 |
| `GET /api/files/{fileId}/download` | 파일 다운로드 | 공개 |
| `DELETE /api/files/{fileId}` | 파일 삭제 | 게시글 작성자 |

업로드는 `multipart/form-data` 요청이며 필드 이름은 `files`입니다. 같은 필드를 반복해 한 요청에 1~5개를 전달합니다. 파일마다 10 MiB(10 × 1,024 × 1,024바이트) 이하, 전체 요청은 50 MiB 이하입니다. 전체 요청 제한에는 multipart 부가 데이터도 포함됩니다.

Swagger UI의 파일 업로드 API에서 `postId`를 입력하고 `files` 항목에 파일을 선택해 전송합니다. 로그인 후 CSRF 토큰을 다시 발급받은 상태여야 합니다.

업로드 응답은 `201`, 목록 응답은 `200`이며 모두 아래와 같은 JSON 배열입니다.

```json
[
  {
    "id":3,
    "originalFilename":"설명서.txt",
    "size":120,
    "contentType":"application/octet-stream",
    "downloadUrl":"/api/files/3/download"
  }
]
```

`size`의 단위는 바이트입니다. 저장용 UUID·서버 디렉터리는 응답하지 않습니다. 다운로드는 `downloadUrl`로 요청하며 `application/octet-stream`, `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff` 헤더와 파일 내용을 반환합니다. 한글 원본 파일명은 다운로드 이름에 반영합니다.

빈 파일은 거부합니다. UNIX·Windows 원본 경로는 제거하고 마지막 파일명만 보관하되, `..` 경로 구성요소·제어문자·공백뿐인 이름·255자를 초과하는 이름은 거부합니다. 예를 들어 `C:\fakepath\설명서.txt`는 `설명서.txt`로 보관하고 `../설명서.txt`는 거부합니다. 실제 파일은 지정된 업로드 디렉터리에 UUID로 저장합니다.

업로드 트랜잭션 실패 시 새 파일을 정리하고, 삭제 시 DB 커밋 후 실제 파일을 삭제합니다. DB와 파일시스템은 원자적 트랜잭션이 아니므로 강제 종료·삭제 실패 시 파일이 남을 수 있습니다. 정리 실패는 서버 로그에 기록되며 저장소 문제를 해결한 뒤 해당 UUID 파일을 수동 정리해야 합니다.

## 웹 화면 구현 현황

`GET /`는 로그인 없이 게시글 목록 HTML을 제공합니다. 검색·페이지 이동·페이지 크기 변경은 `GET /api/posts`에 연결됩니다. 제목을 누르면 `GET /post.html?id=게시글ID`로 이동하여 본문·첨부파일·댓글을 조회합니다. 상세 화면은 로그인 세션이 있으면 댓글 작성·본인 댓글 수정·삭제와 본인 게시글 삭제를 지원합니다. 상태 변경 시 CSRF 토큰을 다시 조회하고, 실패한 요청을 자동 재시도하지 않습니다.

`/post.html?preview=1`은 API 요청·DB 저장 없이 예시 콘텐츠로 디자인을 확인하는 읽기 전용 모드입니다. 실제 쓰기와 다운로드는 실행하지 않습니다. 게시글 작성·수정·로그인·회원가입 화면은 준비 중 안내를 표시하며, 해당 API는 Swagger UI에서 사용할 수 있습니다.

## 오류와 검증 현황

오류 응답 예시:

```json
{"message":"게시글을 찾을 수 없습니다."}
```

| 상태 | 발생 조건 |
| --- | --- |
| 400 | 입력 검증·JSON·페이지 오류, 중복 이메일, 빈 파일, 파일 개수·이름 오류 |
| 401 | 로그인 실패 또는 로그인 필수 API에 세션 없음 |
| 403 | CSRF 토큰 누락·불일치, 다른 작성자의 데이터 수정·삭제 |
| 404 | 게시글·댓글·파일 없음, 댓글의 게시글 경로 불일치 |
| 409 | 동시 변경 요청 충돌, 재시도 필요 |
| 413 | 파일당 10 MiB 또는 전체 multipart 요청 50 MiB 초과 |
| 500 | 파일 저장소 등 서버 내부 처리 오류 |

CSRF 검증은 로그인 판정보다 먼저 실행됩니다. 상태 변경 요청에 세션과 CSRF 토큰이 모두 없다면 `401` 대신 `403`이 먼저 반환될 수 있습니다.

`clean test bootJar`와 총 **74개 테스트**가 통과했습니다. 인증 18개, 게시판 API 30개, 실제 HTTP 흐름 1개, 첨부파일 서비스 7개, 파일 저장소 18개를 포함합니다. 실제 HTTP 테스트는 세션 쿠키·한글 파일 내용·업로드 용량 제한도 확인합니다. 자동 테스트 DB는 H2입니다.

목록·상세 화면 추가 후 전체 `test`를 다시 실행해 **90개 테스트가 통과**했습니다. 추가된 16개는 익명 HTML·정적 리소스·HEAD 응답과 기존 API 인증 보호를 실제 HTTP로 확인합니다. 공통 API JavaScript도 mocked fetch 기반 검증 13개를 통과했습니다.

별도로 Docker Compose 이미지 빌드와 앱·MariaDB 11.4.13 실행 및 Swagger 응답을 확인했습니다. 실제 MariaDB 환경에서 회원가입·세션 로그인, 게시글 작성·조회·삭제, 댓글 작성·수정, 한글·이모지 파일명 업로드와 원본 바이트 다운로드를 검증했습니다. 앱·DB 컨테이너 재생성 후에도 계정·게시글·댓글·첨부파일이 유지되며, 게시글 삭제 시 댓글·첨부파일 메타데이터 및 실제 파일이 정리되는 것을 확인했습니다. 검증용 임시 데이터는 모두 삭제했습니다. 초기 소스와 문서는 [GitHub 저장소](https://github.com/4xolotl/Spring-Boot-)에 업로드했습니다.
